# Dynamic Dashboard

The existing four statistic cards, calendar, attendance card, fee donut and activity list keep their original colors, classes and layout. Sample figures and sample badges were removed. Teachers, Attendance and Holidays already exist in this project and are used. Fees and Expenses are not implemented, so financial totals currently show zero.

## Commands

Run from the project directory. With XAMPP and PHP absent from PATH, replace `php` with `C:\xampp\php\php.exe`.

```powershell
php artisan migrate
php artisan cache:clear
php artisan view:clear
npm run build
php artisan test
```

No seed is needed for the Dashboard. No demonstration events or activities are created. On a new installation only, existing academic defaults can be installed with:

```powershell
php artisan db:seed --class=AcademicSetupSeeder
php artisan db:seed --class=SubjectSeeder
php artisan cache:clear
```

Then sign in as Admin, open **Settings / Academic Setup**, and select **Current academic session**. If none is selected, student and attendance widgets are empty. Students without that session assignment are excluded. The migration initially selects a matching existing `YYYY-YYYY` or `YYYY-YY` session if one exists. If the sessions table or `is_current` field is absent in an older installation, the service falls back to all active students.

`storage:link` is only relevant to student photos and is not required by these Dashboard widgets. Existing Admin credentials continue to work; event management is Admin-only.

## Counting and caching

- Student totals include only `Active` students in the current session, excluding soft-deleted records. Boys and girls are grouped counts, not loaded student rows.
- Teachers and classes are filtered by Active status when that column exists. Existing academic tables have no status column, so all their records count. Sections are currently shared academic options; the count reflects their actual table records.
- Attendance uses today's records for eligible current students. Legacy title-case statuses are normalized. Present/absent/late bars use the total eligible students as denominator; the headline percentage is `(present + late) / total students`. Unmarked, leave and half-day records do not count as full present. No marked records gives 0% and “Attendance not marked yet”.
- Calendar events and existing holidays appear together. Every day in an inclusive date range gets a dot. Initial and monthly responses include dates for the entire 42-cell calendar, including adjacent-month cells. The list underneath shows the next three upcoming or ongoing events. Selecting a date lists that day's events.
- Each widget uses `Cache::remember` for five minutes. A revision key invalidates all widget variants without requiring a tag-supporting cache driver. Old entries expire automatically. Keys include the local date, preventing yesterday's values being reused after midnight.
- Model observers cover students, sessions, classes, sections, teachers, attendance, holidays, events, admissions and promotions. Transactions invalidate immediately and again after commit. Bulk attendance services explicitly invalidate. Raw SQL/imports that bypass model events must call `DashboardStatsService::invalidate()` after their transaction, or run `cache:clear`.
- Activity records are persisted alongside transactional workflows; rolled-back changes do not leave activity rows. The feed stores original event timestamps and formats relative time freshly with Carbon.
- Date badges and calendar “today” use the configured `Asia/Karachi` timezone. The logged-in user comes from the existing web session.

## Future fee module adapter

No fee tables or fake balances are created. Missing or unsupported schemas safely show zeros. The service supports these common columns:

| Table | Date column, in preference order | Amount columns |
| --- | --- | --- |
| `fee_vouchers` | `due_date`, `date`, `created_at` | Billed: `total_amount` or `amount`; pending: `balance`, `balance_amount`, `remaining_amount`, or billed minus `paid_amount`/`amount_paid`. Last fallback is full amount for unpaid/pending/partial status. |
| `fee_payments` | `payment_date`, `paid_at`, `date`, `created_at` | `amount` or `paid_amount` |
| `expenses` | `expense_date`, `date`, `created_at` | `amount` or `total_amount` |

Current month date boundaries are inclusive start / exclusive next month. If an academic-session column exists it is scoped; student-linked records otherwise use eligible students. Donut percentage is collected / billed, with safe zero division and a circle capped visually at 100%. The number remains the actual ratio. When implementing Fees, adjust this adapter to the final schema (including cancellations, refunds, allocations and payment-only balance calculations), register its model observer or explicitly invalidate after writes, and add a `fees.index` named route. Until then the fee card has no unavailable destination.

## Manual checks

1. **Students:** select the current session in Academic Setup, add an Active student with that session, refresh Dashboard; the total and Boys/Girls note update immediately. Change status, edit, archive or promote; refresh and verify counts and activity entries. Students in another session do not count.
2. **Teachers / Classes:** compare totals with active teacher records and actual class/section records. The cards open their existing pages. With no teachers, the note reads “Not added yet”.
3. **Attendance:** mark today's attendance for a current-session class, then refresh. Verify present/absent/late counts and bars against the roster. With no records today, check 0% and the unmarked message.
4. **Fees:** this installation shows Rs. 0 and a 0% donut with “No fee data yet”; no fee module is installed. Automated tests exercise real aggregate calculations against temporary supported finance tables.
5. **Calendar:** as Admin, open **Notices**, add an exam/meeting with dates and an existing palette color, then return to Dashboard. Check its dots, click a date, browse next/previous months, and use Today. Edit/delete the event and verify cache refresh. Existing Attendance holidays also appear.
6. **Activities:** create/edit/delete a student, approve an admission, or run a promotion. The latest five records appear with type icons and relative times. Previous operations are not invented or backfilled.
7. **Header:** sign in and check your name and role in the top bar, plus Karachi's current date in the header. Signed-out viewers show Guest.
8. **Empty data:** `php artisan test --filter=DashboardTest` verifies rendering when tables are empty or module tables are absent, without altering your real database.
